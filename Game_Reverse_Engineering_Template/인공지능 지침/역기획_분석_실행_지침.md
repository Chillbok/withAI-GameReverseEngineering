# Reverse Engineering Analysis Execution Guidelines

This document contains specific instructions for the analysis and evaluation of reverse engineering documents and the generation of reports.

## 1. Analysis and Evaluation Criteria
1. **Accuracy**: Verify the consistency between the official data in `게임에 대한 정보/` and the content of the document being analyzed.
2. **Mechanisms**: Analyze whether the strategic elements of the target game genre are appropriately reflected.
3. **Logistics/Logic**: Evaluate the logical validity of the established values or rules.
4. **Actionability**: Propose specific solutions (values, formulas, logic, etc.) that the user can directly apply to improve the document.
5. **Comparability**: Provide before/after comparisons to clearly explain the logic of the improvement.

## 2. Report Writing and Storage Rules
- **Storage Location**: **`인공지능의 분석 문서들/`** folder.
- **Filename Format**: **`YYYYMMDDTHHmm 인공지능 역기획 분석.md`**.
- **Writing Principles**:
    - Do not write the entire document on behalf of the user.
    - Focus on explaining what is wrong and exactly how it should be changed.
    - Focus on "actionable guides" and comparisons so that users can improve it themselves.
- **Template Usage**: Use the [[인공지능 분석 보고서 템플릿]] and include `ai_model` in the YAML frontmatter.

## 3. Asset and Link Management
- **Asset Management**: All external attachments such as PDFs or images should be saved in the **`System/Assets/`** folder and linked within the document.
- **Link Handling**:
    - External documents (Notion, etc.): Use Markdown hyperlinks (`[Document Name](url)`)
    - Local documents: Use **`[[Wikilinks]]`**.

## 4. Language and Terminology
- All responses and document generation must be in **Korean**.
- Use terminology appropriate for the game's world and follow translations found in reference documents.
